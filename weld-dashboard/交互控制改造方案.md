## 〇、三项决定的落实

1. **控制区位置**：由我决定 → 放在**左侧「实时采集区」竖长块下方**。理由：采集区是整个流程的起点（传送、拍照、成像切换都发生在这里），把控制条贴在它下面，操作者的视线和手不用在画面与控制之间来回跳，符合从上到下的作业直觉。
2. **缺陷判定方式**：**随机判定**。保留真实检测的不确定性，每次点击结果可能不同，更贴近实际。
3. **日志视图形式**：**右侧滑出面板**（抽屉式）。从屏幕右侧滑入，不遮挡主看板，看完即收起。

## 一、为什么要改（不变）

现状是"自动播放的演示片"：三条画面自己循环，工件自动流过、按固定概率自动变缺陷、自动触发一切。人只能看，无法介入，也无法回答演示中最常被追问的"这个缺陷怎么来的""能现在拍一张吗""记录在哪"。

目标：把看板从**被动演示动画**升级为**可操作的仿真控制台**。所有关键动作由人触发，动作 → 画面变化 → 数据变化 → 日志留痕的因果链清晰、可复现、可讲述。外观与现有布局保持不动。

## 三、B 检测端：完整功能（做什么 + 为什么）

### 3.1 产线控制（流程主干）

**6. 启动传送带**
传送带开始/停止。启动后工件在彩色与检测画面中流动；停止时工件驻留在检测位。为什么：这是全流程的总开关，采集与检测都以"有工件在流动或被驻留"为前提；能停才能对"当前这一件"做检测。

**18. 启动良品率实时监控**（对应原常驻曲线）
把现在"一直在自动滚动"的良品率曲线，改为由按钮启动/暂停。为什么：让监控成为可控动作而非背景动画，与传送带启停呼应，答辩时可明确说"现在开始监控"。

### 3.2 图像采集（相机侧）

**7. 触发 D435i 拍照**
定格当前一帧为一张照片，采集画面出现快门反馈，照片进入样本库并高亮。为什么：让"采集"从背景动画变成一个具体、可讲述的动作——"我刚拍了这一张"。

**8. 查看深度图 / 彩色图切换**
在彩色画面与深度画面之间切换主视图，切换时状态标识同步更新。为什么：真实工位用彩色图看外观缺陷、深度图看焊缝轮廓起伏，双模态切换体现 D435i 的成像能力。

**9. 调节曝光 / 增益参数**（新增）
提供曝光、增益两个可调参数，调节后采集画面的明暗与噪点实时变化。为什么：真实相机采集必须调参，过曝/欠曝会直接影响后续检测效果；有了它，"拍照"才像真的在调相机，而不是点一下出图。

**10. 连续采集 10 件工件**
一次操作连续抓取 10 件/帧，过程中显示采集进度，完成后形成"待检批次"。为什么：模拟产线连续过件，同时为"批量检测"准备数据；强调采集与检测是两个独立步骤。

### 3.3 检测与实验（算法侧）

**11. 加载 YOLO 模型**
状态从"未加载"变为"模型就绪"，检测类操作在此之前不可用。为什么：真实系统必须先加载推理模型才能检测，这个前置条件让流程有"上电—就绪"的真实语义，也让后续按钮的可用性有依据。

**12. 单张检测（检测当前帧）**
对当前驻留工件/刚拍的那一帧做识别。按你确认的**随机判定**给出结果：命中则标记缺陷框、触发剔除、缺陷入库、日志+1。为什么：核心动作，把"拍照"和"判定"分开，让人亲手完成一次"采集 → 识别 → 处置"。

**13. 批量检测并统计**
对待检批次逐张检测，逐条出结果，并汇总本批次良品数、缺陷数、各类缺陷数。为什么：体现工业场景的吞吐能力；一次操作看到多条结果，便于演示统计与分布。

**14. 置信度阈值实验**（新增）
提供可调的置信度阈值；改变阈值后对同一批数据重新判定，观察检出数量的变化。为什么：这是 YOLO 检测最核心的实验——阈值越高越"保守"（漏检多、误报少），越低越"激进"。它能直观展示 precision/recall 的权衡，是答辩里很有说服力的一个交互。

### 3.4 结果呈现与追溯（分析侧）

**15. 查看缺陷占比饼图**（新增）
新增一个缺陷类型占比饼图视图（焊穿/未焊透/咬边各自比例）。为什么：现有进度条擅长比较大小，饼图擅长表达"整体构成"，两者互补；饼图是评审最熟悉的表述方式。

**16. 查看准确率迭代曲线**
把现有静态的 82%→94% 迭代曲线，做成可"调出/聚焦查看"的交互。为什么：内容已有，但成为一个人主动触发的动作后，讲解时才能说"我们来看准确率曲线"，而不是让它在角落里自生自灭。

**17. 人机对比**
把现有 94%（AI）/ 87%（人工）对比卡，增强为一个可触发的对比视图（准确率、速度、漏检等维度）。为什么：这是体现 AI 价值最直接的证据，值得单独作为一个可展示动作。

**22. 设备报警处置**（新增）
当出现连续缺陷、参数越限等异常时触发报警（状态条/弹窗提示），并提供"确认/复位"处置动作。为什么：闭环必须有"异常处理"这一环，否则系统只能演示顺利的情况；有报警与处置，才像真实运行的设备。

### 3.5 执行机构（分拣侧）

**19. 查看 PLC 状态面板**
点击设备区的 PLC 卡片，调出详细状态面板（运行状态、IO、通信等）。为什么：现有只有运行时长和状态灯，把"看状态"深化为"查面板"，体现工业现场的可观测性。

**20. 观察机械臂码垛**
把当前"缺陷→机械臂剔除"之外，增加良品"码垛"动作的演示入口。为什么：真实产线机械臂既剔除缺陷品也码放良品；现有只有剔除计数，补上码垛动作让执行环节完整。

**21. 观察气缸剔除**（新增）
增加一个"气缸剔除"的执行机构演示：缺陷品经气缸推出剔除。为什么：剔除有多种执行方式，机械臂抓取与气缸推出是产线上最常见的两种；补上它，"剔除"环节才有对比和选择。

## 四、D 多模态交互（做什么 + 为什么）

这五项定位为**演示级模拟**：在当前单机看板内做出可信的交互效果，不接入真实语音服务/外部检索引擎/第二块物理屏幕。

**34. 语音模态：语音查询**
提供语音入口，说一句话即可查询（如"查一下焊穿缺陷"），系统以文字+高亮结果回应。为什么：语音是自然交互的前沿形态，演示"能听懂人话"比点按钮更有记忆点。

**35. 文本模态：跨模态检索**
提供文本输入框，输入关键词（缺陷类型、工件编号、时间段）即可检索，结果联动到图像与日志。为什么：文本是最通用的检索模态，也是语音识别结果的落点；"跨模态"体现在一次检索能同时带出文字记录和对应图像。

**36. 图像模态：四模态联动**
以图为入口：点选一张缺陷照片，联动展示它的语音描述、文本记录、相关统计与检测数据（即语音/文本/图像/数据四模态协同）。为什么：这是多模态的核心卖点——不是四种模态各干各的，而是"从一个模态切入，其他模态跟着动"。

**37. 看板 DIY 布局**
允许拖拽调整面板位置/大小，并可保存自定义布局。为什么：真实看板都要按岗位定制（质检员关注缺陷、班组长关注良品率），DIY 布局体现"以人为中心"的可配置性。

**38. 双屏联动演示**
在两个浏览器窗口/屏幕间联动：一端操作，另一端实时同步展示。为什么：真实车间是"操作屏 + 大屏"分离的，双屏联动演示贴近部署形态，也适合答辩现场一大一小两块屏展示。

## 五、完整操作闭环（更新版）

把主干串起来，操作者可以手动走完一整遍：

```
加载模型 → 启动传送带 → [调曝光/增益] → 拍照 / 连续采集×10
        → [彩色/深度切换、置信度阈值实验] → 单张检测 / 批量检测并统计
        → 缺陷判定（随机） → 气缸/机械臂剔除 + 良品码垛 + 缺陷数据保存
        → 查看饼图 / 准确率曲线 / 人机对比 / PLC状态
        → 异常时设备报警处置
        → 通过滑出面板查询缺陷日志（语音/文本/图像多模态检索）
```

每一步都有对应的可见反馈，任意一次缺陷都能从画面追溯回日志条目。

## 六、系统状态与反馈（做什么）

- **未加载模型**：检测类操作不可用，提示"请先加载模型"。
- **模型就绪**：检测条件满足，相关按钮解锁。
- **传送带运行中 / 已停止**：控制工件是否流动。
- **采集中 / 检测中**：批量操作显示进度，避免误以为卡住。
- **报警态**：异常时高亮提示，需处置后复位。
- **已存证**：缺陷入库后的确认反馈。

为什么：真实设备有严格的工序依赖和状态反馈；模拟这一点，操作才有因果感，演示才经得起追问。

## 七、缺陷数据留存与日志查询（做什么 + 为什么）

**保存**：每条缺陷独立留存——工件编号、类型、置信度、时间、照片。留存动作可见（日志数+1、样本库新增、状态提示"已存证"）。为什么：计数只能答"有多少"，追溯要答"哪一件、何时、长什么样"；可追溯是工业质检的核心价值。

**查询**：从右侧滑出的日志抽屉，按类型/编号/时间段检索，查看每条记录的照片与详情，并支持语音/文本/图像多模态检索入口。为什么：日志是"按需查看"的数据视图，滑出式既不占主画面，又让"查记录"成为流程里一个明确、可演示的动作。
